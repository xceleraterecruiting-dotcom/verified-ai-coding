# Invariants

Format: `- INV-<id> [L<0-3>] <testable predicate>`. The level tag is the invariant's own risk
class. Lens-derived invariants are marked in their text.

## Invariants

- INV-1 [L3] No content, chunk, embedding match, citation, or title from a document the requesting principal is not authorized to read may ever enter the retrieval set, the model prompt context, or the rendered answer; ACL filtering is applied at or before vector/lexical search, and a post-generation filter alone never satisfies this invariant.
- INV-2 [L3] A query whose only relevant documents are unauthorized for the principal must produce a response indistinguishable in content, citations, and error shape from the no-matching-document case; the system must never emit an access-denied message, title, or any other existence signal for a specific unauthorized document.
- INV-3 [L2] A document whose permission metadata is missing, unparseable, or in an unrecognized schema must be quarantined as most-restricted (readable by no principal) and excluded from indexing until a human remediates it; it must never default to readable by anyone (lens-derived fail-closed default, A5).
- INV-4 [L2] Every factual answer must cite at least one source document that was actually present in the query's ACL-filtered retrieval set; a citation to a document outside that set (fabricated, or unauthorized) must never be rendered.
- INV-5 [L2] When the ACL-filtered retrieved documents do not support an answer to the question, the assistant must decline; this is enforced by output-side groundedness verification, not solely by prompt instruction.
- INV-6 [L2] Permission decisions must use principal entitlements no staler than the configured staleness bound (value pending OQ-3); an offboarded principal or a revoked membership must fail closed once the directory reflects it, and entitlement resolution failure must deny, not allow.
- INV-7 [L2] Every generated answer must persist its model id, prompt version, run/trace id, and the exact retrieved source passages supplied to the model, linked to the answer (lens-derived, AI-output lens items 1–4).
- INV-8 [L2] System prompts, raw model output/errors, stack detail, and other principals' queries or answers must never appear on any user-visible surface; internal failures degrade to a generic safe message.
- INV-9 [L2] The launch gate must emit exactly one of PASS, FAIL, or INSUFFICIENT_EVIDENCE; evidence below the sufficiency thresholds (sample size, coverage, recency — values pending OQ-2), stale evidence, or contradictory evidence must land in INSUFFICIENT_EVIDENCE (no-go), never in PASS (lens-derived, evidence-sufficiency lens item 4).
- INV-10 [L2] Every dashboard/launch metric must have pinned semantics — numerator, denominator, exclusions, and what it cannot show — and a proxy must never be reported as the claim it proxies (in particular: presence-of-citation must never be reported as groundedness) (lens-derived, evidence-sufficiency lens item 2).
- INV-11 [L2] Eval evidence produced before a change to the model id, prompt version, retrieval configuration, or ACL normalization mapping is void for launch decisions; the gate must detect the version mismatch and refuse to count voided evidence (lens-derived, evidence-sufficiency lens item 5).
- INV-12 [L2] The eval harness must include negative controls: seeded restricted documents with planted queries crafted to elicit them; a harness run in which a seeded leak case fails to be detected as a leak when deliberately un-filtered is a failure of the harness itself, and any canary leak in normal operation is a FAIL of the gate (lens-derived, evidence-sufficiency lens item 9).
- INV-13 [L2] Any LLM judge whose output gates launch (e.g., groundedness grading) must have its false-positive and false-negative rates measured on a human-labeled set before its output counts as gating evidence (lens-derived, evidence-sufficiency lens item 8).
- INV-14 [L2] The requesting principal's identity must be provider-attested (IdP/SSO); team/role/exec entitlements must derive from the authoritative directory; no identity or entitlement may be accepted from client-supplied input (lens-derived, identity lens).
- INV-15 [L2] Every query must produce an audit record containing the principal, the entitlement snapshot reference, the documents considered and filtered, the answer-or-decline outcome, and the generation record reference; audit storage is itself access-restricted so the audit trail cannot become a leak vector (lens-derived, AI-output lens item 15).
