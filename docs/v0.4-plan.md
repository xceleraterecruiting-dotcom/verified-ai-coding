# v0.4 — Local verification-loop orchestrator (plan)

**Honest name:** the **verified-run scaffolder** (the script) + **local verification-loop orchestrator** (the whole thing). It scaffolds artifacts, validates them, runs the existing fresh-context reviewer, and drafts outputs. It does **not** implement code, commit, push, merge, deploy, or call external APIs. Not a self-driving engineer — a loop helper with mandatory human gates.

## 1. Install + path-resolution (the centerpiece)

**Problem:** `SKILL.md` references like `` `templates/feature-contract.md` `` resolve relative to the working project, so they break when a skill is installed globally and you're in another repo.

- **A — rewrite references to absolute `~/.verified-ai-coding/` paths at install (RECOMMENDED).** In-repo sources keep relative refs (work when the repo is open); the installer rewrites known prefixes (`templates/`, `prompts/`, `scripts/`, `agents/`) to absolute `~/.verified-ai-coding/…` when copying each `SKILL.md` into `~/.claude/skills/`, then **validates every rewritten path exists** and fails loud otherwise.
- **B — inline templates into SKILL.md.** Rejected: bloats skill files, duplicates content, risks truncation, breaks standalone templates.
- **C — manual clone / relative paths.** Rejected: the status quo we're fixing.

**Installer:** `scripts/install-global.mjs` (Node, no deps): copy `templates/ prompts/ scripts/ agents/` → `~/.verified-ai-coding/` (keeps `scripts/` + `prompts/` adjacent so the reviewer config is unchanged); copy each skill → `~/.claude/skills/<name>/` with refs rewritten; validate; print restart note. `--dry-run`, `--uninstall`, idempotent. Evidence pointers (`probe/`, `examples/`) stay repo-relative (informational, not rewritten).

## 2. Run-folder convention
Project-local: `.verified-ai/runs/<YYYY-MM-DD>-<slug>/` with `request.md`, `contract.md`, `enforcement-path.md`, `redteam-plan.md`, `implementation-plan.md`, `allowed-forbidden-files.md`, `test-output.md`, `review-bundle.md`, `reviewer-result.md`, `remediation-plan.md`, `final-scorecard.md`, `pr-body.md`.
- **Scaffolded + Claude-filled before code:** request, contract, enforcement-path, redteam-plan, implementation-plan, allowed-forbidden-files.
- **Produced after implementation:** test-output (scoped), review-bundle (assembled), reviewer-result, remediation-plan (only if NEEDS_REVIEW/FAIL), final-scorecard, pr-body.
- Decision: in XR-Main (private), commit run folders as the proof trail (toggle to gitignore if noisy).

## 3. Orchestrator: `scripts/verified-ai-loop.mjs` (one script, subcommands)
`new` / `status` / `bundle` / `review` / `finalize`. **May:** create folders, copy templates, validate artifacts, assemble bundles, call `independent-review.mjs` (config #3, unchanged), parse + fail closed on INVALID, draft scorecard/PR body. **Must not:** implement code, run/scope tests itself, commit, open PRs, merge, deploy, call external APIs, change schema. `finalize` refuses without a PASS.

## 4. Slice-scoped gates
No repo-wide pass/fail (XR-Main has ~600 pre-existing tsc errors). Convention: `npx vitest run <slice test>` and `npx tsc --noEmit | grep <touched files>` → pasted into `test-output.md`; `bundle` validates it's non-empty with a result marker, never interprets global status.

## 5. Automation boundaries
- **Script-automated:** run-folder creation, validation, bundle assembly, reviewer run+parse+fail-closed, scorecard/PR-body drafting.
- **Claude-automated (under approved contract):** request/contract/enforcement/redteam/implementation, scoped tests, bounded remediation.
- **Approval-gated:** scope, schema, egress, commit, PR, merge/deploy, out-of-scope files, destructive commands.
- **Manual-only:** merge/deploy, secret rotation, anything outward.

## 6. Safety rules
Allowed/forbidden file check; no schema/egress/commit/PR/merge/deploy without approval; reviewer INVALID blocks PASS; deterministic gates outrank the reviewer; proof artifacts must exist before commit.

## 7. Daily XR UX
`new` → Claude fills contract/redteam/etc → **you approve scope** → implement in allowed files → scoped tests → `bundle` → `review` (PASS/NEEDS_REVIEW/FAIL/INVALID; remediate if needed) → `finalize` → **you approve commit/PR**.

## 8. Orchestrator self-tests
Deterministic, no git/network: `new` creates folder+stubs; `bundle` fails closed on missing artifact; `review` parses PASS/NEEDS_REVIEW/FAIL/INVALID; `finalize` refuses without PASS; asserts no git invocation.

## 9. Risks
Same-vendor reviewer + ToolSearch/Task* residual; path-resolution fragility (mitigated by install-time validation); messy-repo gates (slice-scoped); implementation still Claude-dependent; framework bloat (hard MUST-NOT list, scaffolder-not-agent); run-folder git noise (commit-vs-ignore decision).

## 10. Recommendation
Build it — **after** the interview-facing README (proof #04 already makes the interview story complete; v0.4 is for daily use). Phases:
- **Phase 1 (real milestone):** `install-global.mjs` (A + validation) → run-folder convention → `verified-ai-loop new`. Stop and use it before building more.
- **Phase 2:** `bundle` / `review` / `finalize`.
- **Phase 3:** daily XR workflow docs.
- **Later:** hooks, CI, different-vendor reviewer.

**First implementation slice:** `install-global.mjs` (approach A + path validation) — prerequisite and riskiest; de-risk first.
